# SwipeNodes｜长语音消息跨设备摘要与多模态交互

**用AI把长语音组织成可访问的重点，用耳机与戒指的硬件触摸滑动，在总摘要、分段重点和原始声音之间导航。**

本项目结合用户研究、LLM工作流、自制触摸硬件与软件播放控制。核心是小触摸面上的信息导航；手机界面提供可视参照、统一播放控制与实验观测。最终硬件方案为**等分节点映射＋最后经过节点吸附（Last-Crossed Snap）**。

## 场景与问题

步行提物、运动、家务等多任务情境下，用户无法持续查看手机。长语音的线性收听让“掌握大意”和“查找细节”依赖完整播放；错过关键信息后又需要重听。单一摘要虽然缩短内容，却不能完全替代原始语气、细节与情绪。

项目因此关注：如何让用户先理解整体，再通过轻量触摸定位所需信息，并保留回到原声的路径。

## 从研究到功能定义

作品集第6页及论文§3.1记载两轮焦点小组，研究长语音处理痛点、摘要需求和非视觉导航要求。归纳出的设计方向为：减少口语冗余；支持滑动式非视觉导航；使用层级摘要；定向访问与重放重点；保留原声以理解情绪。

这些要求被转化为**总摘要 → 少量分段重点 → 对应原文**的结构。触摸节点需要既能区分，又能与音频片段可靠关联，因此AI不能只输出一段自然语言，还要提供可被交互系统消费的结构化结果。

## AI工作流与产品机制

**语音 → Whisper转写 → 文本清洗 → 消息分类与情绪补充 → 时间对齐分段 → 类型提示词生成结构化摘要 → 原文／时间校正 → 摘要语音与节点播放。**

- **提示词路由：**任务类强调行动和截止时间，通知类强调事实与生效信息，闲聊类保留人际语气与上下文。
- **控制信息粒度：**将内容收敛为少量重点，适配耳机柄与戒指有限的触摸空间。
- **数据契约：**总摘要、分摘要、时间范围、原文片段、消息类型等字段连接AI输出、前端和硬件导航。
- **回退与溯源：**时间戳缺失时采用VAD或均分；解析失败重试或降级；保留原文入口供用户核对。不能因此保证摘要无幻觉。

## 三类消息与工程数据

任务类保留行动与截止时间，通知类保留事实与生效信息，闲聊类保留话题与情绪。当前LLM按标签路由到不同提示词；RoBERTa训练代码是另一路探索。

工程主标注文件有1000条记录：任务335、通知337、闲聊328；只有805条不同清洗文本。另有54条模型对比材料，三类各18条，参考摘要为空。它们是工程文件记录数，数据采集或合成来源尚未核实，不是研究参与人数。

已整理数据转换、分类训练与摘要对比代码，但未发现可核实的逐类分类F1或混淆矩阵。情绪字段匹配率不等于消息分类准确率。详见[消息类型与数据核查](docs/message-types-and-data.md)和[聚合数据](analysis/message-type-aggregate.json)。

## 软硬件关系

| 组成 | 实际角色 |
| --- | --- |
| 耳机刚性触摸板／戒指柔性触摸面 | 捕获电容变化，提供硬件滑动输入，是核心交互研究对象 |
| ESP32控制板 | 论文描述多通道采样、位置估计与滤波，输出0–100%位置 |
| 串口监听与Node／Socket.IO | 在硬件输入和网页播放状态之间传递位置、触摸／松手事件 |
| 手机／网页 | 显示相同信息节点，作为硬件触摸参照，承接统一播放与实验记录 |
| 系统音频与耳机 | 浏览器定位播放后，由操作系统通过蓝牙音频输出供用户收听 |

已核对的接入方式是**串口控制链路＋操作系统蓝牙音频链路**。论文提及BLE能力，不等同于当前存档已实现独立无线控制产品。

硬件考量包括电极布局、小面积触摸的误触与容错、刚性／柔性材料的噪声差异、阈值和平滑、安装留白、控制板与连接器复用。所检存档中尚未找到固件与PCB工程，无法独立重建硬件；论文的电极数和采样通道数也需进一步核对。

## 最终方案与可用性测试条件

| 内容 | 研究用途 | 最终选择 |
| --- | --- | --- |
| 无极、等分、非等分 | 比较触摸空间映射 | 等分 |
| 区间、吸附 | 比较松手时目标节点的选择 | 最后经过节点吸附 |

**等分**指触摸空间中的节点等距，不要求原始音频片段等长。**吸附**指保留最后经过的节点，不是找到几何上最近的点；它用于减少手指经过提示点后继续惯性移动导致的选错。

手机参照组可以偏好连续操作，这不改变穿戴硬件最终采用等分＋吸附的方案。上述模式是可用性测试条件，不是五个并列的最终用户功能。

## 完整任务与可体验Demo

收到消息 → 听总摘要 → 判断是否需要细节 → 在耳机／戒指上滑动选择重点 → 数字节点提示 → 松手后吸附目标节点 → 听对应重点与原声 → 继续或结束。

网页参照Demo沿用1.0播放器，默认等分＋吸附。历史对照选项仅在展开“可用性测试条件”后出现。原1.0的吸附松手逻辑位于Chat父组件的硬件事件分支，此次将机制移植至鼠标参照路径；鼠标不能复现真实电容信号、佩戴与反馈体验。

体验消息、摘要与语音是本次另制的合成示例，不是用户研究数据或实时AI结果。两段视频展示原项目与实体触摸操作，可在展示页播放。

## 研究与评估

作品集保留形成性研究、交互迭代和三个测试部分：

1. **Study1：设备与映射。**比较手机参照、耳机、戒指上的滑动映射；后续Study1b比较区间与吸附判定，支持最终硬件机制选择。
2. **Study2：摘要质量。**比较基线LLM与提示词路由摘要。稿件报告清晰、简洁与覆盖之间的取舍，不能笼统声称所有指标都更好。
3. **Study3：跨场景任务。**比较概览与重点定位，评估设备和情境适配。稿件明确驾驶条件为固定基座模拟器／乘客位复现，不应写成实际道路驾驶验证。
