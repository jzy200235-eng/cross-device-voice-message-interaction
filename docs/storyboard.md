# 完整任务：硬件触摸为主，手机界面为参照

优先查看作品集原页8–10、12、14。以下文字只解释原方案，不添加新交互。

| 步骤 | 用户与硬件 | 软件与AI的职责 | 反馈与信息 |
| --- | --- | --- | --- |
| 接收 | 不便看手机时，通过耳机了解消息 | ASR、分类路由、分段与摘要产生结构化节点 | 总摘要交代消息大意 |
| 判断 | 决定是否需要细节 | 保留总摘要与分段原声的关联 | 少量重点形成可导航结构 |
| 选择 | 在耳机柄或戒指触摸面滑动 | 电容位置通过串口与Socket.IO进入播放状态；等分映射节点 | 经过节点时给出数字提示 |
| 松手 | 在目标附近松手，即使稍有惯性滑过 | 吸附到最后经过的节点，而不是按最终落点简单归入相邻区间 | 保留刚确认的目标 |
| 获取 | 收听该重点与对应原声 | 播放器按时间锚点定位，系统路由声音至耳机 | 确认具体内容和语气 |
| 继续 | 继续访问其他节点，或结束 | 维持同一组节点与播放状态 | 无需每次从头重听 |

手机界面显示同一结构，便于参照触摸输入和记录测试，不取代硬件核心。原作品集中的回复与日程扩展不纳入本条1.0核心任务。触觉、佩戴和电容信号的真实表现须以实体原型为准；浏览器声音提示不能替代它们。
