# AI工作流与软硬件接入

## 项目定位

SwipeNodes是一项将AI语音处理、嵌入式触摸输入与音频导航连接起来的研究原型。核心创新是耳机／戒指小触摸面上的节点导航；手机网页承担参照、统一播放控制与实验观测，不是项目核心创新的替代品。

AI侧需要把非结构化语音变为**硬件可以稳定访问的少量节点**。硬件侧则要让用户不持续看屏幕，也能找到这些节点。两部分通过结构化摘要、时间锚点和播放状态协同，而非单纯把一段摘要显示到手机上。

## 工作流及产品决策

| 阶段 | 输入 → 输出 | 对交互的意义 | 证据与实现边界 |
| --- | --- | --- | --- |
| 识别 | 音频 → 转写及时间信息 | 能回到对应原声，而非只有文字摘要 | 论文4.1；1.0 `segment_pipeline.py`与`segmenter.py` |
| 清洗 | 原始转写 → 去口语冗余文本 | 减少理解负担 | 1.0为规则清洗，不等同于完善的语义去噪 |
| 分类与路由 | 文本 → task/notice/chitchat | 任务重行动与截止时间，通知重事实与时效，闲聊保留人际语气 | 1.0调用LLM并选择类型提示词；异常时回退task |
| 情绪补充 | 转写 → 文本情绪标签 | 帮助摘要保留语境；不代替原声情感 | 已见文本LLM路径；不据此宣称实际完成声学情绪识别 |
| 分段 | 时间戳／VAD／均分 → 少量片段 | 将信息数量限制在小触摸面可导航的范围 | 优先ASR，缺失时VAD，再均分；合并短片段 |
| 结构化摘要 | 类型提示词＋片段 → 总摘要与分摘要JSON | 统一AI与前端的数据契约 | `overall_summary`、`segments`、`time_range`、`original_fragment`、`msg_type`、`emotion`等 |
| 对齐与回退 | LLM结果 → 规范化片段 | 尽量避免摘要与原声错位；保留溯源入口 | 1.0修正段数、强制时间范围；仅在原文缺失时补入系统原文，不能声称彻底消除幻觉 |
| 音频与节点消费 | 摘要语音＋原声片段 → 统一播放结构 | 总摘要→重点→原声；硬件、手机共享节点身份 | 音频合成/拼接存在其他脚本；不把全部功能归入单个Python入口 |

论文主流程使用Whisper与GPT-4o-mini，并讨论Qwen等可替换模型。1.0默认模型与代理配置依具体入口而异。当前展示采用预置合成数据，没有在线运行这条AI链路。

### 论文与1.0的差异

- 论文给出80字／150字及1–3段等规则；1.0 `segment_pipeline.py`以120个清洗后字符为阈值，收敛到2或3段。展示不混为同一实现。
- 论文强调系统提供时间范围和原文并校正。1.0强制覆盖时间范围，但只在LLM原文缺失时补原文；完整原文一致性仍需后续核验。
- JSON解析失败会重试“仅返回JSON”；再次失败后保留截断输出和空片段，属于降级，不是成功生成有效摘要的保证。
- 预置重音字段、可选韵律模块或论文目标，不自动等于当前入口已产生可靠重音信息。

## 从触摸到声音的实际连接

**电容触摸电极 → ESP32多通道采样与加权位置估计 → 串口0–100%位置流 → `serial-listener.js` → Socket.IO服务器 → 浏览器状态与节点判定 → HTMLAudioElement定位／播放 → 操作系统蓝牙音频路由 → 耳机。**

可核对的1.0实现：

1. 串口监听默认115200波特率，通过行解析器取得位置；同时发出`continuous_slider_update`及`hardware_touch_state`。
2. 有效数据到达时触摸设为active；约150ms没有新数据后发送松手状态。这是接收端推断，不等同于独立压力传感器直接测量松手。
3. Node服务接收位置、触摸状态并通过Socket.IO广播；网页跟踪正在播放的消息和硬件覆盖位置。
4. 硬件拖动时记录候选目标；松手时，区间模式用当前区间起点，吸附模式优先使用最近一次播报的节点，再恢复此前播放状态。
5. 声音由浏览器播放，经操作系统的蓝牙音频路由输出到耳机。控制信号和音频信号是不同链路；不是Web Bluetooth直接控制整套硬件。

BLE是论文所述ESP32平台能力，不能因此推定当前存档已经跑通无线控制、OTA或独立产品。现有串口桥接和服务也不是生产级设备配对协议。

## 硬件设计考量

依据论文4.2.2：

- **形态与复用：**同一控制板与连接器设计支持耳机刚性FR-4触摸板、戒指柔性FPC触摸面，便于在不同佩戴位置比较交互。
- **触摸面与误触：**电极纵向布置，考虑小面积滑动、安装留白和意外激活；等分节点让空间目标可预测。
- **噪声与阈值：**刚性板与柔性板的噪声不同；柔性面需要更高阈值、额外平滑。论文还描述背面走线与寄生电容／耦合噪声的考量。
- **采样到位置：**电容通道通过加权平均得到连续位置，低通滤波抑制抖动。数字节点提示帮助用户知道“刚经过哪个节点”，再由吸附容忍惯性滑过。
- **供电与连接：**稿件描述ESP32、DC-DC与FPC接口集成在四层PCB中；这属于稿件记载，当前存档未找到可独立重建的固件、PCB与校准工程。

注意：稿件同时出现“六个电极”和“采样五通道”的描述，需要以最终硬件图／固件核对。不能把这些细节包装成已独立复现的硬件规格。原型的能耗、触摸延迟与无线稳定性也没有在本次整理中实测。

## 最终机制与实验条件

用户已确认最终硬件方案为**等分映射＋最后经过节点吸附（Last-Crossed Snap）**。

- 无极、等分、非等分是Study1a比较的空间映射。
- 区间、吸附是Study1b比较的节点选择策略。
- 等分不要求原始音频等长；是把节点等距映射到触摸空间。
- 吸附保留最后经过的节点，不是松手后选几何最近点。这样手指略微滑过目标、再松手时不必落进相邻区间。
- 手机参照组可偏好连续控制，不改变最终穿戴硬件采用等分＋吸附的选择。

1.0中`seekPolicy`的有效松手分支位于Chat父组件的硬件事件监听中，而非独立AudioPlayer内部。此次参照Demo将该机制移植到鼠标松手路径；它用于讲解相同判定，不宣称鼠标复现了电容触摸噪声与佩戴条件。测试模式选择控件默认隐藏，仅在“展开可用性测试条件”后显示。
