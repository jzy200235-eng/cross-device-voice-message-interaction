## 可体验部分

本地审阅版复用1.0的`AudioPlayer`及其样式，另加演示入口和预置合成消息。32.2秒音频由本机语音合成生成，总摘要和三个分摘要均为本次另写示例，不经过实时AI。

上一轮已通过播放与控件切换检查；本轮进一步发现切换控件不足以证明吸附机制，已将硬件父组件的松手机制移植至鼠标参照路径，并补充媒体Range支持后重新检查实际定位。本轮以同一路径从触摸轴60%滑至49%：区间判定落在6.53秒，吸附判定保留50%节点对应的15.53秒，证明两者在合成参照任务中实际不同；这不是用户实验数据。补充修复本地媒体服务Range响应，解决浏览器音频不可寻址问题。上一轮桌面1440px和手机390px宽度检查未发现横向溢出。两段视频均已读到时长与可用媒体数据。

展示副本修改：补齐原进度条点击处理函数中缺失的`onSeek(targetTime)`；为播放键补充可访问名称；默认固定等分＋吸附，将其他选项置于测试对照入口；将硬件松手吸附机制移植至鼠标参照。没有改写完整研究系统或增加新设备交互。

## 运行条件与缺口

- 展示页：Python 3静态服务即可，无在线依赖。
- 提取播放器：Node.js、React及react-scripts；已构建静态文件，可直接用审阅服务运行。
- 原始网页：在`web-last/client`安装依赖并执行`npm run build`；后端需在`web-last`安装依赖并执行`npm run server`。现有配置默认前端代理与API端口为5000；更改端口需同步前端配置。
- 在线处理：Python依赖见`Voice_Summary_Project/requirements_api.txt`；需自行准备允许使用的音频、可用模型/API配置、音频工具与必要模型资源。存档依赖表并不覆盖所有可选入口，未验证全量环境安装。
- 硬件：现存串口脚本默认`COM3`、115200波特率；macOS需对应串口路径。没有在本次检查中确认固件、接线和硬件校准条件。
- 完整聊天与音频处理不能仅靠静态GitHub Pages运行；浏览器体验版可以在权限确认后作为静态子页面发布。
- API失败、旧账号缺失、录音权限、TTS与音频资源缺失均可能影响完整工程。基础接口通过不等于完整系统端到端通过。
